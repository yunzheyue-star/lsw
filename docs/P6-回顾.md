# P6 回顾：文件系统（Z: / CIFS）

> 记录范围：P6 阶段从 QEMU user-mode SMB 到 host root Samba 的架构演进、真机问题定位、最终验收结果与经验教训。本文档用于追溯，不替代接口文档；接口以 `docs/interfaces/` 为准。

## 目标与交付

- Linux → Windows：Windows 内 `Z:` 指向 Linux `$HOME`；
- Windows → Linux：把 guest 的 `C$`/`D$` 通过 `mount.cifs` 挂到 `/mnt/Windows/{C,D}`；
- 凭据安全：Windows 密码不进入 argv/日志，优先 keyring，其次交互输入，最后环境变量；
- 最小权限：CIFS 挂载与 host Samba 启停都经 `scripts/lsw-mount-helper`；
- 真机验收：`lsw start` 返回 VM/CIFS/Z:，同一 SSH 会话可 `Set-Location Z:\` 并读写。

## 最终架构

```text
Windows guest                         Linux host
------------                         -----------
Z: \\10.0.2.2\qemu  --SMB2/3-->
                                      QEMU user-net 网关 10.0.2.2:445
                                      → 127.0.0.1:445
                                      → root smbd（helper smb_start）
                                      [qemu] path=$HOME，匿名/force user

C$/D$ <--SMB server on guest:445--   mount.cifs //127.0.0.1/C$
                                      port=1445（QEMU hostfwd）
```

- `lswd` 在 `start` 时经 helper 启动 root `smbd:445`，`shutdown` 时停止；
- QEMU **不再**使用 `smb=` / user-mode SMB，也不使用 `guestfwd`；
- `Z:` 映射按 Windows 登录会话隔离：`start` 只启动 host Samba 并报告 `z_drive`，真正的 `net use` 延迟到使用 `Z:` 的 SSH 会话（P6 验收脚本、P7 `lsw shell`、P8 exec）。

## 关键问题与定位过程

1. **QEMU user-mode SMB 的 SMB1 依赖**
   - Windows 10 默认 `SMB1Protocol-Client` 全部 Disabled，表现为 445 能连、`net use` 假成功、`Set-Location` 报 53。
   - 临时方案是 guest 启用 SMB1 并重启，验证 `Z:` 可访问。

2. **QEMU user-mode SMB 的会话脆弱性**
   - 即使启用 SMB1，每个 Windows 启动周期只有部分会话能稳定建立；P6 step 6 映射成功后，step 8 新 SSH 会话仍可能 53。
   - 尝试过 QEMU `guestfwd + 每连接 bridge + host Samba`：裸 TCP/回显双向验证通过，但 Windows SMB 多会话仍会卡死，最终放弃。

3. **host root Samba + `10.0.2.2` 网关**
   - 用 sudo 在宿主 `127.0.0.1:445` 启动 root smbd，共享 `$HOME` 为 `[qemu]`；
   - guest 通过 QEMU user-net 网关 `10.0.2.2:445` 访问，SMB2/3、多会话稳定；
   - 真机对照脚本验证：`Test-NetConnection 10.0.2.2:445 = True`，`net use Z: \\10.0.2.2\qemu` 可列目录。

4. **daemon 提前映射占用首次会话**
   - 若 `lsw start` 在自身 SSH 会话内先 `net use`，后续 step 8/新会话可能 53；
   - 改为 `start` 只启动 host Samba，`ZDriveMapper` 由使用会话调用。

5. **验收脚本 UNC 转义 bug**
   - `scripts/lsw-p6-real-test.sh` 的 PowerShell 串曾生成 `\\10.0.2.2\\qemu`（host 后多一个反斜杠），Windows 持续报 53；
   - 修正为 `\\10.0.2.2\qemu` 后 30/30 通过。教训：验收脚本必须校验最终传给 PowerShell 的字符串。

## 经验教训

- **盘符按登录会话隔离**：Windows 的 `net use` 不能跨 SSH/桌面会话继承；映射应在当前会话内完成。
- **不要依赖 QEMU user-mode SMB 做生产共享**：SMB1 在现代 Windows 默认禁用，且多会话不稳定；host Samba 更可控。
- **提权边界**：host Samba 与 CIFS 都用同一最小权限 helper；密码只走 stdin/keyring。
- **脚本验收要打印真实错误**：`Out-Null` 会掩盖 53/121 等关键报错；本次最终靠 `net use` 原始输出定位到 UNC 转义。
- **回退路径**：如后续要禁用 SMB1：`Disable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol-Client -All -NoRestart` 后重启 guest；当前 host Samba 方案不依赖 SMB1。
